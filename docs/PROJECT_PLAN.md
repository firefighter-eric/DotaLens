# DotaLens 项目规划

## 1. 项目目标
- 打造一个基于 npm 生态的 Dota 数据分析 Web App（无需上架 App Store）。
- 为玩家提供「胜率趋势 + 英雄表现 + 段位分布」的一站式分析视图。
- 保持前端架构清晰，可快速接入真实 Dota 数据源（OpenDota / Stratz 等）。

## 2. 用户与核心场景
- 用户画像：有复盘和上分需求的 Dota 玩家、战队分析人员、内容创作者。
- 核心场景：
  - 查看近 7/14/30 天胜率趋势。
  - 对比各英雄胜率、KDA、GPM 与综合影响力。
  - 判断自己常打对局的段位分布。

## 3. 功能范围
- 已实现（MVP）
  - 仪表盘概览卡片（总场次、综合胜率、平均 KDA、最佳英雄）。
  - 14 天胜率趋势图。
  - 英雄表现数据表。
  - 段位分布可视化。
- 下一步（V1）
  - 接入真实 API，支持玩家 ID 查询。
  - 时间筛选（近 7/14/30 天）。
  - 英雄筛选、定位筛选、数据排序与导出。
- 进阶（V2）
  - 阵容克制分析、装备时间线分析。
  - 多账号/队友协同复盘。

## 4. 技术方案
- 前端：React + Vite（纯 npm 项目）。
- 代码组织：
  - `src/components`：可复用 UI 组件。
  - `src/data`：当前阶段的 mock 数据。
  - `src/utils`：统计计算逻辑。
- 工程规范：
  - npm scripts：`dev` / `build` / `preview` / `lint`。
  - ESLint（基础规范 + React Hooks 规则）。

## 5. 里程碑计划
- 里程碑 A（已完成）：搭建基础工程与可运行 UI。
- 里程碑 B（1-2 天）：接入真实 API 并统一数据模型。
- 里程碑 C（1 天）：增加筛选、排序与错误状态。
- 里程碑 D（1 天）：补充测试、性能优化与部署配置。

## 6. 质量与验收标准
- 本地可通过 `npm run dev` 启动。
- `npm run build` 成功。
- 页面在桌面端和移动端可用，布局不破坏。
- 数据结构与计算逻辑解耦，便于后续扩展。

## 7. 风险与应对
- API 限流或响应结构变化：增加缓存层与容错映射。
- 单页面信息密度高：分模块拆页 + 过滤器渐进显示。
- 可视化复杂度提升：引入图表库前先做数据接口抽象。
