# DotaLens 产品规划文档（PRD）

## 1. 文档信息

- 产品名称：DotaLens
- 文档类型：当前版本范围 + 里程碑计划
- 当前版本：v1.3（与代码现状同步）
- 更新时间：2026-03-01
- 适用仓库：`React + Vite` 前端项目（本仓库）

## 2. 当前产品状态（已实现）

### 2.1 信息架构

- Tab 工作台：
  - `最近对局`
  - `英雄池`
  - `趋势`
  - `段位`
  - `总览`
  - `全英雄`
  - `全物品`

### 2.2 核心能力

- 双 ID 输入：Steam32 与 OpenDota ID。
- 账号管理：最多 5 个账号本地保存与快速切换。
- 时间窗口：7/14/30 天。
- 仪表盘摘要：总场次、胜率、平均 KDA、最佳/最差/最常玩英雄。
- 胜率趋势：按天聚合折线图 + 最新/峰值/低点解读。
- 英雄池分析：
  - 排序（影响力、场次、胜率、KDA、GPM、XPM、名称）
  - 属性筛选
  - 最少场次过滤
  - CSV 导出
  - 行展开查看该英雄窗口内对局
- 最近对局：10/20/30 场切换 + 汇总统计。
- 对局详情抽屉：
  - 基础概览（模式、队列、KDA、KP 等）
  - 个人核心数据
  - 出装与技能
  - 全场玩家面板（含伤害占比、装备、净值）
- 本地目录浏览：
  - 全英雄（属性分类 + 详细属性卡）
  - 全物品（类别分类 + 图标目录）
- 国际化：zh/en 双语。

### 2.3 鲁棒性

- 请求中断：保留 `AbortController`。
- 错误映射：404 / 429 / 其他状态码本地化提示。
- 空数据场景：返回可解释空态，不阻塞整体页面。
- 示例数据：在真实数据不可用时可保持可浏览界面。

## 3. 数据与架构基线

### 3.1 分层职责

- `App.jsx`：全局状态（查询、账号、tab、筛选、抽屉）与编排。
- `services/opendotaClient.js`：接口请求、参数兜底、错误翻译。
- `services/opendota.js`：业务聚合与 ViewModel 组装。
- `utils/metrics.js`：纯计算（dashboard summary、recent summary）。
- `components/*`：纯展示组件。

### 3.2 当前数据契约（核心）

`fetchPlayerWindowAnalytics` 返回：

- `playerName`
- `heroPerformance[]`
- `dailyWinRate[]`
- `rankDistribution[]`
- `recentMatches[]`
- `windowMatches[]`
- `metrics`
- `totalMatches`
- `latestMatchStartTime`

`fetchRecentMatchDetail` 返回：

- `matchId` / `hero` / `heroAvatar`
- `overview`
- `core`
- `build`
- `allPlayers[]`

## 4. 版本里程碑

### M1（已完成）

- 基础查询、14/30 天窗口、趋势/英雄/段位展示。
- 中英文切换、错误提示与 mock 数据。

### M2（已完成）

- Tab 化工作台。
- 最近对局面板。
- 英雄池增强（排序/筛选/导出/展开）。
- 账号本地多账号管理。

### M3（已完成）

- 对局详情抽屉（含全场玩家面板）。
- 全英雄/全物品目录 + 本地素材同步脚本。
- 7 天窗口补齐。

### M4（下一阶段）

- `段位` Tab 补充分路分布（当前仅展示段位分布）。
- URL 状态同步（tab / days / account）。
- 对局列表高级筛选（胜负、英雄、段位区间）。

### M5（中期）

- Hero 详情专题（单英雄趋势、对线样本）。
- 双账号对比（自己 vs 队友/对手）。
- 分享与导出增强（视图快照）。

## 5. 验收标准

### 5.1 工程检查

- `npm run lint` 通过。
- `npm run build` 通过。

### 5.2 功能回归

- 双 ID 查询成功。
- 账号切换与持久化正确。
- 窗口切换后各 Tab 数据同步。
- 最近对局与英雄行内明细均可进入详情抽屉。
- 中英文文案完整、无缺失 key。
- `<=980px`、`<=640px` 不破版。

## 6. 风险与应对

- OpenDota 限流/抖动：保留错误可解释性，并保持可浏览状态。
- 数据字段不稳定：聚合层统一兜底，避免渲染层分散处理。
- 文案增量导致遗漏：PR 检查强制同步 `zh/en`。

## 7. 非目标（当前阶段）

- 不引入重型状态管理库。
- 不迁移 TypeScript。
- 不重构 Vite/ESLint 工具链。
